The skill that separates Easy from Medium is mapping a problem statement to a pattern in under a minute. This is that lookup table, plus the reasoning behind each entry.

**Map the phrase to the pattern.**

| The problem says | Reach for |
|---|---|
| "two numbers that sum to..." unsorted | hash map |
| "two numbers that sum to..." **sorted** | two pointers |
| "triplet" / "pair" with a property | sort, then two pointers |
| "longest/shortest **substring** with..." | sliding window |
| "longest/shortest **subarray** with..." | sliding window (prefix sums if negatives) |
| "**subarray** sum equals k" | prefix sums + hash map |
| "count/frequency/duplicate/anagram" | hash map or Counter |
| "range sum queries" | prefix sums |
| "sorted array" + O(log n) | binary search |
| "minimum X such that condition holds" | binary search on the answer |
| "kth largest/smallest" | heap (or quickselect) |
| "top k" | bounded heap of size k |
| "median of a stream" | two heaps |
| "merge k sorted..." | heap |
| "next greater/smaller element" | monotonic stack |
| "valid parentheses/nesting/matching" | stack |
| "window maximum/minimum" | monotonic deque |
| "shortest path", unweighted | BFS |
| "minimum number of steps/moves" | BFS |
| "level by level" | BFS with `len(q)` snapshot |
| "connected region" / "island" / "flood fill" | DFS or BFS on a grid |
| "all paths" / "all combinations" / "all subsets" | backtracking |
| "prerequisites" / "dependency order" / "build order" | topological sort |
| "can all courses be finished" | topological sort (cycle detection) |
| "are these connected" with edges arriving over time | union-find |
| "count the ways" | DP |
| "min/max over a sequence of choices" | DP |
| "intervals" / "merge" / "schedule" | sort, then greedy sweep |
| "maximum non-overlapping" | sort by **end**, greedy |
| "merge overlapping" | sort by **start**, greedy |
| "single number" with O(1) space | XOR |
| "subsets" with `n <= 20` | bitmask |
| BST + "kth smallest" or "validate" | inorder traversal |
| "in place" / O(1) space | two pointers, or reuse the input |

**Read the constraints — they are hints.** Input size tells you the intended complexity, which tells you the pattern.

| Constraint | Intended complexity | Likely pattern |
|---|---|---|
| n ≤ 10 | O(n!) | permutations, brute force |
| n ≤ 20 | O(2ⁿ) | bitmask, subsets, backtracking |
| n ≤ 100 | O(n³) | 2-D DP with an inner loop |
| n ≤ 1,000 | O(n²) | 2-D DP, nested loops |
| n ≤ 10⁵ | O(n log n) | sort, heap, binary search |
| n ≤ 10⁶ | O(n) | hash map, two pointers, sliding window |
| answer fits in a range | O(log range) | binary search on the answer |

If you see `n <= 20`, stop looking for a clever linear solution — the problem expects exponential search. If you see `n <= 10^5`, an O(n²) approach will time out and you need to find the O(n log n) one.

**Decision tree for a Medium you do not recognize.**

```
Is the input sorted, or would sorting help?
  yes -> binary search, or two pointers
Is it about a contiguous run?
  yes -> sliding window (prefix sums if negatives or a sum condition)
Is it about counting or lookups?
  yes -> hash map
Is it a tree?
  need info flowing down -> preorder
  need info from children -> postorder
  it's a BST and order matters -> inorder
  by level -> BFS
Is it a graph?
  shortest path -> BFS
  explore/components -> DFS
  ordering/prerequisites -> topological sort
  dynamic connectivity -> union-find
Does it ask for ALL of something?
  yes -> backtracking
Does it ask for a count of ways, or min/max over choices?
  yes -> DP.  Can I justify a greedy choice? Then greedy.
Is there nesting or "next greater"?
  yes -> stack
Is it about k best elements?
  yes -> heap
None of the above?
  write brute force, get it correct, then look for repeated work to eliminate
```

That last line is the genuinely important one. A correct brute force plus an honest attempt to optimize scores far better than an unfinished clever solution.

**Complexity by pattern — know these without thinking.**

| Pattern | Time | Space |
|---|---|---|
| Hash map single pass | O(n) | O(n) |
| Two pointers | O(n) | O(1) |
| Sliding window | O(n) | O(k) |
| Prefix sums | O(n) build, O(1) query | O(n) |
| Binary search | O(log n) | O(1) |
| Binary search on answer | O(n log range) | O(1) |
| Sort then sweep | O(n log n) | O(n) |
| Heap top-k | O(n log k) | O(k) |
| Tree traversal | O(n) | O(h) |
| BFS / DFS on a graph | O(V + E) | O(V) |
| Topological sort | O(V + E) | O(V + E) |
| Union-find | O(1) amortized per op | O(n) |
| Backtracking subsets | O(n · 2ⁿ) | O(n) + output |
| Backtracking permutations | O(n · n!) | O(n) + output |
| 1-D DP | O(n) or O(n·k) | O(n), often O(1) |
| 2-D DP | O(m·n) | O(m·n), often O(min(m,n)) |

**Edge cases to check on every problem.** Run this list before declaring done:
- Empty input — `[]`, `""`, `None` root.
- Single element.
- Two elements — catches most off-by-one errors.
- All identical elements.
- Already sorted, and reverse sorted.
- Negative numbers, and zero.
- Duplicates — allowed? do they change the answer?
- The target at the very beginning or very end.
- For trees: single node, and a completely skewed tree.
- For graphs: disconnected components, self-loops, a single node.
- Integer overflow — not in Python, but say so if the interviewer expects another language.

**Deliberately out of scope for this topic,** so you know where the boundary is rather than worrying about gaps: AVL and red-black trees (you should know *that* balanced BSTs give O(log n), not how to implement one), B-trees and B+ trees, segment trees and Fenwick trees, suffix structures, KMP and Rabin-Karp, network flow, and heavy-light decomposition. None of these are expected at Easy or Medium.

Two things sit just past the boundary and are worth picking up once the patterns above are solid: **tries**, which appear in a few Mediums like Implement Trie and Word Break optimization; and **Dijkstra's algorithm**, which is BFS with a heap for weighted shortest paths.

**The five highest-leverage patterns**, if you only have time for a few: hash map, two pointers, sliding window, BFS/DFS, and 1-D DP. Those five cover a very large share of Medium problems, and every other pattern on the list is easier to learn once they are automatic.
