Binary search halves the search space each step, giving O(log n). Interviews test two things: writing it without off-by-one bugs, and recognizing the harder variant — **binary search on the answer**, where there is no sorted array in sight.

**The basic template.** Use this exact shape and the off-by-one problems disappear.

```python
def binary_search(nums: list[int], target: int) -> int:
    left, right = 0, len(nums) - 1          # inclusive bounds
    while left <= right:                    # <= because bounds are inclusive
        mid = left + (right - left) // 2    # avoids overflow in other languages
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

Three details that matter:
- Bounds are **inclusive**, so the loop condition is `left <= right`. If you use an exclusive `right = len(nums)`, the condition becomes `left < right`. Pick one convention and never mix them.
- `mid = left + (right - left) // 2` rather than `(left + right) // 2`. In Python integers are arbitrary precision so overflow is not real, but interviewers in other languages expect this, and it costs nothing.
- Always move past mid: `mid + 1` or `mid - 1`. Assigning `left = mid` is the classic infinite loop.

**The more useful template: find the boundary.** Most real problems are not "find this exact value" but "find the first position where a condition becomes true". This version generalizes better and I would default to it.

```python
def first_true(lo: int, hi: int, predicate) -> int:
    """Smallest x in [lo, hi] with predicate(x) True, else hi + 1.
    Requires predicate to be monotonic: False...False True...True."""
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if predicate(mid):
            hi = mid              # mid might be the answer, keep it
        else:
            lo = mid + 1          # mid is definitely not
    return lo
```

The invariant: the answer is always in `[lo, hi]`. When the predicate holds at mid, mid is a candidate so you keep it; when it fails, mid is excluded so you move past it. Almost every binary search problem reduces to defining the right monotonic predicate.

**Python's built-in.** Know that `bisect` exists and what the two functions do:

```python
import bisect
bisect.bisect_left(a, x)    # first index where a[i] >= x  (insert before equals)
bisect.bisect_right(a, x)   # first index where a[i] >  x  (insert after equals)
```

`bisect_left` is the lower bound, `bisect_right` the upper. Together they give the range of equal elements, which solves "find first and last position of target" in two calls. Mention the built-in, but be ready to hand-write it — many interviewers ask for the implementation.

**Variant: rotated sorted array.** The array is sorted but rotated; the trick is that one half is always properly sorted.

```python
def search_rotated(nums: list[int], target: int) -> int:
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        if nums[left] <= nums[mid]:               # left half is sorted
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        else:                                     # right half is sorted
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
    return -1
```

The `<=` in `nums[left] <= nums[mid]` matters for the two-element case. Trace `[3, 1]` looking for 1 to see why.

**Variant: find the minimum in a rotated array.** Simpler, and a good demonstration of comparing against the right endpoint.

```python
def find_min_rotated(nums: list[int]) -> int:
    left, right = 0, len(nums) - 1
    while left < right:
        mid = left + (right - left) // 2
        if nums[mid] > nums[right]:
            left = mid + 1        # minimum is strictly right of mid
        else:
            right = mid           # mid could be the minimum
    return nums[left]
```

Compare to `nums[right]`, not `nums[left]` — comparing to the left endpoint does not distinguish the cases cleanly.

**The big one: binary search on the answer.** When the problem asks for a minimum or maximum value that satisfies a condition, and the condition is **monotonic** in that value, binary search the answer space rather than the input.

The signal: "minimum X such that...", "smallest capacity that...", "least time needed to...", plus a feasibility check you can compute in O(n).

```python
def min_eating_speed(piles: list[int], hours: int) -> int:
    """Koko Eating Bananas: smallest speed that finishes within `hours`."""
    def can_finish(speed: int) -> bool:
        return sum((pile + speed - 1) // speed for pile in piles) <= hours

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if can_finish(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

Total complexity is O(n log(max value)) — the log is over the *answer range*, not the array length.

The reasoning to state out loud: "If speed s works, every speed greater than s also works. So feasibility is monotonic in s, which means I can binary search the smallest s that works." That sentence is the insight the problem is testing. The same structure solves Capacity To Ship Packages Within D Days, Split Array Largest Sum, and Minimum Number of Days to Make m Bouquets.

Note `(pile + speed - 1) // speed` as integer ceiling division; `math.ceil(pile / speed)` risks float issues on large values.

**When to reach for binary search.**
- Input is **sorted** (or rotated-sorted).
- The problem says O(log n) is required.
- "Find the first/last position where..."
- "Find the minimum/maximum value such that..." with a monotonic feasibility check.
- Searching a range of answers rather than a collection.
- A matrix with sorted rows and columns.

**Common mistakes.**
- Mixing inclusive and exclusive bound conventions mid-function.
- `left = mid` or `right = mid` in the exact-match template → infinite loop.
- Wrong loop condition for the convention (`<` vs `<=`).
- Binary searching a non-monotonic predicate. The predicate must be False...False True...True; if it oscillates, binary search is invalid.
- Returning `left` when the answer was never found — check `left < n and nums[left] == target` first.
- Forgetting that the answer range for "binary search on the answer" starts at 1, not 0, when zero is nonsensical (a speed of 0 finishes nothing).

**Representative problems.** Easy: Binary Search, Search Insert Position, First Bad Version, Sqrt(x), Valid Perfect Square. Medium: Search in Rotated Sorted Array, Find Minimum in Rotated Sorted Array, Find First and Last Position of Element, Search a 2D Matrix, Koko Eating Bananas, Capacity To Ship Packages Within D Days, Find Peak Element, Time Based Key-Value Store.
